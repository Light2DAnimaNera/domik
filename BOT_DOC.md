# Документация по боту


Проект содержит три независимых телеграм‑бота, расположенных в каталогах `bots/DS`, `bots/DSA` и `bots/DSS`. Общий код вынесен в пакет `shared`.

## Версии

Каждый бот хранит собственный номер версии в файле `bots/<имя>/__init__.py` в переменной `__version__`. Номер состоит из трёх частей `X.Y.Z`:

- `X` — мажорные изменения с добавлением глобального функционала или совершенно нового;
- `Y` — доработка имеющегося функционала;
- `Z` — исправления ошибок и хотфиксы.

Текущая версия всех ботов — `1.1.11`.

## Запуск

Бота можно запустить скриптом `run.py`. Например, `python run.py DS` запустит первого бота (аналогично `DSA` или `DSS`). Также доступны скрипты `run_DS.bat`, `run_DSA.bat` и `run_DSS.bat`.
После вызова скрипта в консоль выводится сообщение вида «Запуск бота DS», где `DS` — выбранный бот.

## Команды бота

- `/start` — спрашивает, есть ли пользователю 18 лет, если его нет в базе. При положительном ответе выводится системное сообщение с правилами, иначе доступ блокируется. Зарегистрированным пользователям бот отвечает «👋 С ВОЗВРАЩЕНИЕМ {username}».
- `/help` — выводит справочную информацию по командам и содержит контакт поддержки @DominaSupremaSupportBot.
- `/begin` — начинает диалоговую сессию и сохраняет сообщения.
- `/end` — завершает текущую сессию и создаёт краткий конспект переписки.
- `/balance` — показывает остаток средств и сегодняшние траты. В ответе используется эмодзи \U0001F4B3. Обе суммы выводятся с точностью до двух знаков после запятой, округляясь в большую сторону, и сопровождаются символом 🝣.
- `/recharge` — выводит клавиатуру с вариантами суммы. После выбора бот просит указать email для отправки чека и лишь затем формирует ссылку на оплату через YooKassa и кнопку для перехода. Пополнение автоматически фиксируется и подтверждается сообщением.
- Введённый email проверяется. При ошибке бот отвечает: «Email введен не верно, укажите корректный email. Он будет использован только для отправки фискального документа.»
- В консоль выводятся логи, отражающие статус оплаты и отправляемые в YooKassa данные от создания счёта до завершения. Дополнительно данные записываются в таблицу `payments`, где для каждого платёжного идентификатора хранится одна запись с текущим статусом, временем `mm-dd-yy HH-MM` и количеством начисленных кредитов. При неудачном обращении к YooKassa бот пишет подробности исключения в лог, что упрощает поиск причины сбоя.
- После статусов `succeeded` или `canceled` платёж удаляется из списка ожидающих и больше не проверяется.
- При успешном пополнении бот DS уведомляет бот DSA текстом
  «НОВОЕ ПОСТУПЛЕНИЕ\nПользователь @username через сервис YooKassa\nОплатил подписку на {amount} ₽».
- Новым пользователям при регистрации автоматически начисляется 100 кредитов.
- Стоимость одного токена запроса составляет `0.0004` единиц, токена ответа — `0.0001`. Значение умножается на коэффициент `token_cost_coeff`.
 - По умолчанию коэффициент равен `12.0`.

Меню команд содержит только пользовательские команды.
В нём также отображается команда `/help`.

Одновременно разрешена только одна сессия. Если пользователю уже доступна активная
сессия, команда `/begin` вернёт сообщение «🛑 СЕССИЯ УЖЕ АКТИВНА\nЗавершите текущую сессию командой /end, затем используйте /begin.».
При внутренней ошибке создание сессии может завершиться ответом «❗ ОШИБКА СОЗДАНИЯ СЕССИИ\nПодождите и повторите /begin.».
Сессия автоматически завершается, если пользователь бездействует 10 минут.
При закрытии по таймауту бот отправляет сообщение «⌛ СЕССИЯ ЗАВЕРШЕНА\nПревышено время ожидания ответа. Начните новую сессию командой /begin.».

## Файлы и функции

### `bots/DS/bot.py`
- Создаёт объект `TeleBot`, регистрирует команды и запускает бесконечный polling.
- Обрабатывает `SIGINT`/`SIGTERM` и по сигналу вызывает `bot.stop_bot()` для корректного завершения работы.

### `bots/DS/bot_commands.py`
- `DEFAULT_COMMANDS` — список команд пользователя.
- `setup_default_commands(bot, *, chat_id=None, username=None)` —
  регистрирует команды для конкретного чата.

-### `database.py`
- `init_db()` — инициализирует базу данных SQLite и создаёт таблицы `users`, `sessions` и `messages` при первом запуске. Таблица `users` содержит поле `blocked` (по умолчанию `0`), определяющее возможность пользоваться ботом.
- `get_connection()` — возвращает новое подключение к базе данных. При создании включает режим WAL, устанавливает `busy_timeout` 5 секунд и задаёт `row_factory = sqlite3.Row`.
- `close_connection()` — функция-заглушка, ничего не делает и оставлена для совместимости.

### `config.py`
- Хранит настройки:
  - `MODEL_NAME` — название модели OpenAI;
  - `CONTEXT_LIMIT` — максимальная длина контекста;
  - `DB_PATH` — путь к файлу базы данных. По умолчанию используется `users.db` в
    корне проекта, значение можно переопределить переменной окружения `DB_PATH`.
  - `DSS_DB_PATH` — SQLite-файл для хранения связей `user_id` ↔ `topic_id` бота
    DSS. По умолчанию это `dss_topics.db` в корне проекта; путь можно задать
    через переменную `DSS_DB_PATH`.
  - `CURRENCY_SYMBOL` — символ валюты, отображаемый в боте.

### `gpt_client.py`
- Класс `GptClient` — обёртка над API OpenAI.
  - `SYSTEM_PROMPT` — основной промпт для общения с моделью. В нём добавлена
    функция `TemporalShift`, считывающая метки времени `[MM-DD-YY HH-MM]`.
  - `SUMMARY_PROMPT` — инструкции для SessionSummarizer v10. Конспект не должен превышать 5000 символов.
  - `__init__()` — создаёт клиента OpenAI с параметрами из переменных окружения.
  - `ask(context, user_text, previous_summary="")` — отправляет запрос и
    возвращает пару `(ответ, usage)` с данными об использованных токенах. Каждая
    строка контекста и текст пользователя снабжаются меткой времени
    `[mm-dd-yy HH-MM]`. Если передан конспект предыдущей сессии, он помещается в
    скрытый блок вместе с текущей отметкой времени перед системным промптом.
  - `make_summary(previous_summary, session_history)` — формирует обновлённый
    конспект, обрезая результат до `SUMMARY_CHAR_LIMIT` (5000 символов). Входные
    параметры передаются строками: первый — прошлое резюме, второй — история
    текущей сессии.

### `models.py`
- `add_user_if_not_exists(message)` — добавляет пользователя в базу, если его там ещё нет.
- `user_exists(user_id)` — проверяет наличие пользователя в таблице `users`.
- `get_all_users()` — возвращает список всех пользователей.

### `session_manager.py`
- Класс `SessionManager` управляет диалоговыми сессиями:
  - `start(user)` — создаёт новую сессию;
  - `ensure(user)` — возвращает активную сессию или создаёт новую;
  - `close(user_id, summary)` — завершает сессию;
  - `active(user_id)` — получает текущую сессию пользователя.
  - `mark_closing(user_id)` — помечает сессию как завершающуюся;
  - `unmark_closing(user_id)` — снимает пометку о завершении.
  - `session_summary(session_id)` — возвращает конспект предыдущей сессии,
    если он был найден при запуске.
  - `update_activity(user_id)` — отмечает момент последней активности.
  - `expire_idle(bot, timeout)` — закрывает неактивные более `timeout` секунд сессии и отправляет уведомление.
  - При закрытии время окончания записывается в базу в формате `mm-dd-yy HH-MM`.

### `message_logger.py`
- Класс `MessageLogger` сохраняет сообщения и формирует контекст диалога:
  - `log(session_id, role, content)` — пишет сообщение в базу и кэш. В колонку
    `created` записывает дату и время в формате `mm-dd-yy HH-MM` (московское время);
  - `context(session_id)` — возвращает историю сообщений в пределах ограничения.
    Каждая строка включает метку времени `[mm-dd-yy HH-MM]` перед текстом.

### `summarizer.py`
- Функция `make_summary(session_id, previous_summary="")` запрашивает из БД роль,
  текст и время каждого сообщения (`SELECT role, content, created ...`) и передаёт
  их `GptClient` вместе с конспектом прошлой сессии. Строки истории формируются как
  `[MM-DD-YY HH-MM] role: text`. Возвращает пару: резюме и полную историю
  переписки.
При запуске новой сессии `SessionManager` ищет сохранённый конспект предыдущей
и, если он найден, передаёт его `GptClient` для скрытого блока
`CONTEXT_PREVIOUS_SESSION_*`.

### `handlers.py`
- Функция `register_handlers(bot)` регистрирует обработчики:
  - `cmd_start(message)` — обрабатывает команду `/start`: если пользователь уже зарегистрирован, бот отправляет `[SYSTEM] ДОБРО ПОЖАЛОВАТЬ`; иначе спрашивает о возрасте и при утвердительном ответе выводит системное сообщение.
  - `cmd_all_users(message)` — обрабатывает команду `/all_users` (только для админа).
  - `cmd_begin(message)` — запускает новую сессию, если другой не активна.
    - `cmd_end(message)` — завершает сессию, сохраняет её краткое резюме и
      выводит полную историю переписки в консоль.
    - `text_handler(message)` — отвечает на текстовые сообщения только при активной
      сессии, иначе просит запустить `/begin`. После списания кредитов выводит в
      консоль, сколько токенов потрачено на запрос и на ответ, и показывает новый
      баланс пользователя.

### `yookassa_payment.py`
- Функции работы с YooKassa:
  - `create_payment(user_id, amount, user_email, credits=None)` — создаёт платёж, выводит в лог отправляемые данные и возвращает объект `Payment`;
  - `payment_status(payment_id)` — проверяет текущий статус платежа;
  - `add_pending(payment_id, user_id, amount, credits)` — регистрирует неоплаченную транзакцию;
  - `list_pending()` и `remove_pending(payment_id)` — управляют списком ожидания;
  - `log_payment(payment_id, user_id, amount, status, credits=0)` — фиксирует статус и начисленные кредиты в таблице `payments`.

### `env.py`
- Загружает переменные из `.env` и экспортирует:
  - `TELEGRAM_TOKEN_BOT1`, `TELEGRAM_TOKEN_BOT2`, `TELEGRAM_TOKEN_BOT3`
  - `OPENAI_API_KEY`
  - `OPENAI_BASE_URL` (по умолчанию `https://api.proxyapi.ru/openai/v1`)
  - `OPENAI_MODEL` (по умолчанию `gpt-4.1-mini`)
  - `SHOP_ID` — идентификатор магазина YooKassa.

```

TELEGRAM_TOKEN_BOT3=<токен третьего бота>
OPENAI_API_KEY=<ключ OpenAI>
OPENAI_BASE_URL=<опционально: адрес API OpenAI>

```

## Бот DSA

Бот `DSA` поддерживает команду `/report`, которая выводит сводку за текущий день.
Такая же информация автоматически отправляется в указанные чаты в 23:59 по
московскому времени. В отчете отображаются новые пользователи, количество и
сумма платежей (в рублях, с символом ₽). Строка «На сумму» показывает, сколько
денег внесли пользователи за день. Также выводится объём первых пополнений за
день. Первая строка отчета выводится как `ОТЧЕТ ЗА 20 июня, 23:59`. В строке
«Из них первый платеж» также ставится символ ₽.
Учитывается только первая операция каждого пользователя, последующие
пополнения в эту сумму не входят.
Число новых пользователей рассчитывается по московскому времени и не зависит от
количества запросов отчёта за день.
Доступ к командам бота имеют только пользователи, перечисленные в переменной
`ADMIN_USERNAME`.
Бот ведет подробный лог действий: выбор аудитории,
сохранение черновиков, планирование и отправка рассылок,
а также формирование ежедневных отчетов фиксируются в консоль.
Команда `/newsletter` выводит инлайн-клавиатуру с цифрами 1–5 и перечисляет варианты
аудитории для рассылки. После выбора кнопки клавиатура скрывается, чтобы
администратор не мог выбрать этот шаг повторно. Бот отправляет сообщение
«выбран вариант X», где X — текст выбранного пункта:
Если команду вызвать повторно до завершения текущей рассылки,
предыдущий черновик автоматически помечается статусом `canceled`.
1. «Все пользователи»
2. «Покупали хотя бы раз»
3. «Баланс < 20 и ни разу не пополняли»
4. «Нет новой сессии > 1 дня»
5. «Ни одной сессии».
После выбора аудитории администратор присылает пост. Он может содержать одно изображение. Бот сохраняет сообщение как
черновик и копирует его обратно с кнопками «Далее» и «Изменить». Если пост содержит изображение,
бот скачивает изображение через текущий экземпляр бота и пересылает его через DS, чтобы получить `file_id` этого бота, после чего удаляет дубль. Первая
подтверждает черновик, вторая удаляет предыдущий вариант и предлагает отправить
новый.
После подтверждения черновика бот спрашивает, когда выполнить рассылку.
Доступны кнопки «Отправить сейчас» и «Отложенный запуск». Во втором случае
требуется ввести дату и время в формате `DD.MM.YYYY HH:MM` по Москве. Если дата
прописана неверно, бот сообщает об ошибке и просит повторить ввод. Если указанная дата и время по Москве меньше или равна текущему моменту, бот отвечает «введенное время уже истекло» и
также предлагает ввести дату и время заново. При корректном значении бот
подтверждает расписание и сообщает:
«Сообщения будут разосланы согласно выбранным критериям».
При выборе «Отправить сейчас» рассылка получает статус `scheduled` и в течение
минуты отправляется планировщиком. После отправки статус сразу меняется на
`sent`, а время фиксируется в поле `sent_at`.
После завершения рассылки в администраторский чат отправляется уведомление
`рассылка с id=<id> отправлена, оповещено N пользователей`, где `N` — количество
получателей. Если в переменной `DSA_REPORT_CHAT_ID` указаны ID чатов, но токен
DSA не передан, сообщение отправит бот DS.

Черновики и запланированные рассылки хранятся в таблице `newsletters` базы
`users.db`. В ней фиксируются текст и изображение сообщения, выбранная аудитория, статус
рассылки и время отправки. Аудитория отбирается функциями `all_newsletter`,
`buyers_newsletter`, `low_balance_newsletter`, `idle_newsletter` и
`no_sessions_newsletter`. Записи со статусом `scheduled` раз в минуту
проверяет фоновый планировщик, запущенный в боте DS. Когда наступает время
отправки, сообщение рассылается выбранной аудитории, поле `sent_at`
заполняется текущим моментом, а статус меняется на `sent`.
Планировщик использует отдельное подключение для каждого обновления статуса и
выводит ошибки в лог без остановки потока.
Дополнительные команды:
- `/nl_list` — список неотправленных рассылок вида `[ID] [дата/время] [audience] [status] «первые 30 символов...»`;
- `/nl_cancel <id>` — отменить рассылку по ID (меняет статус на `canceled`). Если ID существует, бот отвечает «рассылка `<id>` отменена». Если ID отсутствует или уже использован, бот отвечает «ID рассылки указано не верно»;
- `/nl_show <id>` — показать содержимое поста по ID.
- `/coeff` — показать текущий коэффициент `token_cost_coeff`;
- `/set_coeff <значение>` — изменить коэффициент.

Если ID не указан сразу, бот попросит отправить его отдельным сообщением после выбора команды из меню.

## Бот DSS

Бот `DSS` служит связующим звеном между клиентами и операторами.

1. Команда `/start` отвечает фразой «👤 ДОБРО ПОЖАЛОВАТЬ\nПожалуйста, опишите проблему или вопрос. Менеджер свяжется с вами в ближайшее время.».
2. При каждом новом сообщении в личном чате бот ищет связку `user_id` ↔ `topic_id` в таблице `tickets` базы `dss_topics.db`. Если её нет, создаётся новый топик в форуме `DSS_FORUM_ID` с названием «Имя Фамилия • ID» и эта пара сохраняется. 
3. В новый топик первым сообщением отправляется паспорт клиента: имя, `@username` (если указан) и ID. 
4. Текст обращения публикуется отдельным сообщением вида `[Имя] пишет:\n<текст>`. Все последующие сообщения пользователя добавляются в тот же топик тем же способом. 
5. Любые ответы операторов в соответствующем топике бот пересылает пользователю без указания автора, создавая эффект личного диалога. Сообщение приходит от бота DS.
6. Файл `bots/DSS/bot.py` содержит функцию `main()`, запускающую бота.
